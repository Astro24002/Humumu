## 0. 一句话定位

Humumu 帮助用户**发现、筛选和管理学术论文线索**：聚合期刊/预印本的**元信息**，按订阅推送，支持站内已读/收藏/稍后阅读，并通过「查看原文」跳转到 DOI、出版社或预印本原始站点。

**不**托管论文全文，**不**替代出版社或预印本网站。

## 1. 产品定位与边界

### 1.1 用户能做什么

- 从**平台公共目录**发现并订阅学术来源（正式期刊、预印本）；
- **导入**任意兼容的 RSS/Atom 学术来源（私有使用或申请公开）；
- 订阅**作者**与**关键词**；
- 通过 **Email（主通道）** 与 **微信（增强通道）** 接收新论文提醒；
- 在站内浏览更新的**元信息**，标记已读 / 收藏 / 稍后阅读，并**跳转原文**。

### 1.2 第一阶段支持范围

| 纳入 | 说明 |
|------|------|
| 正式学术期刊 RSS/Atom | 主路径 |
| 少量稳定学术 API 源 | 按需（如 Crossref 补 DOI）；非默认全量 |
| 预印本 | arXiv、bioRxiv、medRxiv 等；**单独标识**，不走中科院分区 |
| 平台公共期刊目录 | 含分类筛选与冷启动 seed |
| 用户自定义学术来源 | 私有 / 申请公开 |
| Email 推送 | 主通道；默认每日汇总 |
| 微信推送 | 增强；授权后可用 |
| 每日汇总 + 单来源实时 | 订阅级可覆盖默认频率 |
| 站内阅读状态 | 已读 / 收藏 / 稍后阅读；仅元信息 |

### 1.3 明确不做（第一阶段非目标）

- 无 RSS 期刊的**网页爬虫**；
- 新闻、博客、行业资讯等**非学术**内容；
- 学校自定义分区、复杂团队协作；
- **AI 摘要 / 翻译 / 知识库**；
- 付费与商业化体系；
- 论文**全文**存储或在线阅读器；
- Kafka / Celery / 微服务拆分（第一阶段不需要）。

### 1.4 内容边界（元信息 only）

平台只聚合与展示：

- 标题、作者；
- 期刊或预印本来源；
- 发布时间、抓取时间；
- DOI、原文 URL；
- RSS/API 提供的摘要或简要描述；
- 命中原因（订阅期刊 / 作者 / 关键词等，用于「我的更新」展示）。

用户决定深入阅读时，通过 **「查看原文」** 跳转至 DOI、出版社、期刊官网或预印本原始页面。

站内状态（已读 / 收藏 / 稍后阅读 / 原文点击时间）只作用于**用户私有记录**，不修改公共文章行，不意味着平台持有全文。

### 1.5 公共目录与自定义来源

用户添加来源时二选一：

| 选项 | 行为 |
|------|------|
| **仅自己使用** | 创建者可订阅与使用；**不出现在公共目录**；不进入公共 journals/articles 列表与搜索 |
| **申请公开** | 创建者**立即**可自用；同时进入管理员**待审核**队列 |

公开审核检查：

- Feed 是否可访问、格式是否合法；
- 内容是否确属学术来源；
- 名称与元数据是否完整；
- 是否与已有来源重复；
- 是否能稳定获取条目。

**通过后**才进入公共目录。拒绝则保持私有（或标记拒绝原因），创建者仍可自用（产品默认：拒绝 ≠ 删除私有订阅）。

**「私有」语义（定稿）：**

- 表示**不出现在公共目录与公共 API**；
- **相同规范化 Feed URL 在底层只抓取一次**；其他用户若独立添加同一 URL，可各自订阅，**看不到原创建者身份与其私有状态**；
- 管理员审核可见申请材料，不等于公开。

### 1.6 分类规则

正式期刊公共目录默认采用**中科院分类体系**（独立表，见 §3）：

- 学科大类、学科小类；
- 一区 / 二区 / 三区 / 四区；
- Top 标记；
- 分类年份（默认可展示最新年份；同一刊可属多个小类）。

**分类只用于公共目录的展示、筛选与发现，不直接生成推送。**

预印本：**不参与中科院分区**，使用独立内容类型（如 `preprint`）标识。

### 1.7 第一阶段成功标准（产品层）

不是单纯追求接入格式数量，而是同时满足：

- 覆盖一批主要学科的重点来源（目录冷启动目标见 §4）；
- RSS/Atom 抓取稳定；
- 文章去重准确；
- Email / 微信推送可靠；
- 用户能完成 **发现/导入 → 订阅 → 收到通知 → 浏览元信息 → 标记状态 → 跳转原文** 闭环；
- 能沉淀基础使用数据（订阅激活、原文点击、收藏、退订、抓取/推送失败），支撑后续取舍。

## 2. 信息架构与核心流程

### 2.1 用户端页面（第一阶段）

#### （1）我的更新（登录后默认首页）

只展示**当前用户订阅**产生的新内容（期刊 / 预印本 / 作者 / 关键词命中）。

每条展示：

- 论文标题、作者；
- 期刊或预印本来源；
- 发布时间；
- 中科院分区标签（仅当来源为已公开正式期刊且有分类数据时）；
- 摘要或 RSS 描述；
- **命中原因**（如「订阅期刊」「命中关键词」）；
- **查看原文**（外链）。

可操作：已读、收藏、稍后阅读。

#### （2）期刊目录（公共发现）

筛选维度：

- 学科大类 / 小类；
- 中科院一～四区、Top；
- 正式期刊 vs 预印本；
- 关键词搜索；
- 来源更新/健康状态（对用户可读的摘要，如「正常 / 暂停」）。

可查看：来源元信息、近期更新、订阅人数（若统计），并订阅。

**仅公共且已上架来源**出现在此。

#### （3）添加来源

用户粘贴 RSS/Atom URL，平台依次：

1. 校验地址与协议（见 §3.7 安全）；
2. 探测 Feed，读取名称、描述、站点等；
3. 展示最近若干条预览；
4. 检查是否已有相同规范化 URL；
5. 用户选择 **仅自己使用** 或 **申请公开**；
6. 创建来源并**自动订阅**创建者。

申请公开进入审核队列，**不阻塞**创建者立即使用。

#### （4）我的订阅

集中管理：

- 已订期刊 / 预印本；
- 作者订阅、关键词订阅；
- **每个来源**的推送频率（默认跟随用户默认，可改为该来源实时/每日）；
- **每个来源**的 Email / 微信开关；
- 私有来源及公开审核状态（待审 / 已通过 / 已拒绝）。

产品默认：用户级默认频率为**每日汇总**；重要来源可单独改为**实时**。

#### （5）收藏与稍后阅读

仅保存论文**元信息 + 原文链接**与用户状态；支持按已读/未读/收藏/稍后阅读筛选。无全文。

#### （6）设置

Email、微信绑定、**默认**推送频率、每日汇总时间与时区等。

#### （7）管理后台

- 公开来源审核；
- 重复来源合并；
- 中科院分类维护；
- Feed 抓取健康、失败原因、重试；
- 公共来源上/下架；
- 用户与推送状态查询；
- **真正的管理员角色**（见 §3.8，打破「任意 JWT 即 admin」）。

### 2.2 核心闭环

```
发现公共目录 或 导入 RSS
        → 订阅（自动或手动）
        → 平台按间隔监控来源
        → 每日汇总 和/或 单来源实时通知（Email 主，微信增强）
        → 在「我的更新」浏览元信息
        → 标记已读 / 收藏 / 稍后阅读
        → 「查看原文」跳转 DOI / 出版社 / 预印本站
```

## 3. 底层模型与处理链路

### 3.1 架构原则

- **继续单体**：FastAPI + APScheduler + PostgreSQL + Redis（与迁移后现状同构）。
- **不**为第一阶段引入 Kafka、Celery 或微服务。
- **Journal 仍是学术来源核心实体**，不另建通用 Feed 抽象层。
- 抓取与发送**逻辑解耦**（任务表 + 独立调度），部署仍单进程。

### 3.2 Journal（学术来源）扩展

在现有 `journals` 语义上演进（具体列名以 implementation plan / migration 为准），必要信息包括：

| 概念 | 说明 |
|------|------|
| `content_type` | 正式期刊 `journal` vs 预印本 `preprint`（等） |
| `source_type` | `rss` / `atom` / `crossref` / `pubmed` / …（抓取适配器） |
| Feed URL | **规范化**后的订阅地址（去重与抓取主键之一） |
| 站点 URL | 原始网站 / home（展示用） |
| 目录状态 | 如：`private` / `pending_review` / `public` / `rejected` / `hidden`（下架） |
| 创建人 | `created_by`（可空：系统 seed / 运营录入） |
| 抓取健康 | 最近抓取时间、最近成功时间、连续失败次数、最近错误信息 |
| 条件请求 | ETag、Last-Modified 等 |

可见性规则：

- 公共目录与公共 API：**仅** `public`（及产品定义的上架态）；
- 私有 / 待审 / 拒绝：仅创建者（及管理员审核视图）按权限可见；
- 同 URL 全局抓取一次；多用户订阅同一底层来源时共享文章元数据，**隔离**用户状态与创建者隐私。

### 3.3 期刊分类（独立表）

避免把多年度、多学科塞进 Journal 宽表：

- 分类来源：第一阶段固定 **中科院**；
- 分类年份、学科大类、学科小类、分区（1–4）、Top；
- Journal ↔ 分类：**多对多**（一刊可多小类）；
- 目录默认展示**最新年份**策略（可配置）。

预印本不写中科院分区行；用 `content_type` 区分。

### 3.4 用户订阅

**期刊/来源订阅**每条独立保存：

- 推送频率：默认每日，可改为实时（**覆盖**用户默认）；
- Email 是否启用、微信是否启用；
- 创建时间等。

作者订阅、关键词订阅保留。

**中科院分区不直接生成推送。**

### 3.5 Article（论文元信息）

只存聚合所需字段，例如：

- 标题、作者、摘要/描述；
- DOI、原文 URL；
- 所属来源、发布/抓取时间；
- 来源侧 GUID 等去重依据。

**不**下载、**不**存储全文 PDF/HTML 正文。

### 3.6 用户浏览状态（新）

用户 × 文章 私有状态，例如：

- 已读；
- 收藏；
- 稍后阅读；
- 原文点击时间（用于「原文点击率」等指标）。

不修改公共 `articles` 行。

### 3.7 抓取链路

```
到期来源
  → 安全的条件 HTTP 请求（ETag / Last-Modified）
  → 解析 RSS/Atom（等）
  → 标准化为 Article 元信息
  → 去重
  → 写入/更新元信息
  → 匹配订阅（来源 ∪ 作者 ∪ 关键词）
  → 创建待发送通知 / 推送任务
```

**去重优先级（建议）：**

1. DOI  
2. Feed GUID  
3. 规范化原文 URL  
4. 来源内「标题 + 日期」组合  

**PostgreSQL 唯一约束（或等价幂等约束）是最终防线**；Redis 仅加速（如现有 dedup key），**不得**作为唯一去重依据。

**自定义 RSS 出站安全（硬门禁）：**

- 仅允许 `http`/`https`；
- 拒绝本机、私网、云元数据、保留地址等；
- **每次重定向后**重新校验目标；
- 连接/读取超时、最大响应体；
- 限制解析条目数量；
- 不执行 Feed 内脚本、不主动抓取 Feed 外资源。

### 3.8 推送链路

```
抓取任务写入「待发送」通知/任务
  → 独立后台发送任务（Email / 微信）
  → 记录成功/失败原因
  → 临时失败重试
  → 超过阈值 → 运营可见异常列表
```

- 每日汇总：默认 **Email**；
- 微信：授权后的增强提醒；
- 单来源「实时」：按**该订阅**配置发送；
- **微信失败不得拖垮 Email 主通道**（通道隔离）。

第一阶段实现形态：`notifications`（或衍生 task 表）+ APScheduler 即可，不必上独立 Broker。

### 3.9 权限与数据隔离（相对现网的必要修正）

| 现网问题 | v1 要求 |
|----------|---------|
| Admin 任意登录 JWT 可进 | **真实管理员角色**（或等价 allowlist）；普通用户禁止 admin API |
| 文章/期刊列表偏全局公共 | 公共接口**不得**返回私有来源及其文章；「我的更新」严格按订阅与可见性过滤 |
| 用户 RSS 预览/抓取出站 | SSRF 与体积极限见 §3.7 |
| 推送频率偏用户级 | 订阅级覆盖 |
| Feed 健康弱 | Journal 健康字段 + 后台可查失败/重试 |

## 4. 验收指标与推进路线

### 4.1 内测验收点（第一阶段目标）

- 建立 **200～300** 个经过验证的公共学术来源；
- 覆盖主要中科院学科**大类**；
- 至少 **20** 名真实用户连续使用 **四周**；
- 每名新用户能完成至少一次：目录订阅 **或** 自定义 RSS 导入；
- 形成完整闭环：更新 → 推送 → 浏览元信息 → 标记 → 跳转原文。

### 4.2 可靠性指标

| 指标 | 目标 | 口径提示 |
|------|------|----------|
| 支持范围内 Feed 抓取成功率 | ≥ **98%** | 按调度周期统计成功/应跑次数 |
| 新内容入库时效 | 一个抓取周期内 | 相对该来源 `fetch_interval` 或全局节拍 |
| 重复文章率 | &lt; **1%** | 用户可见 Feed/通知维度，去重合并后 |
| 有效 Email 推送成功率 | ≥ **99%** | 排除非法地址/退订；失败有原因码 |
| 失败可观测 | 100% | 后台可见来源、时间、原因、重试结果 |
| 私有隔离 | 硬性 | 私有来源与其文章**不得**出现在公共目录与公共文章接口 |

### 4.3 内测前必须处理的现有问题（优先级）

1. 管理后台缺少真正管理员角色控制；  
2. 全局文章/期刊列表在引入私有来源后的**泄露风险**；  
3. 用户提交 URL 引发的 **SSRF** / 内网 / 重定向 / 超大响应风险；  
4. 抓取与推送耦合紧、**可靠重试队列**不足；  
5. 推送频率主要是用户级，缺**单来源覆盖**；  
6. Feed **健康状态与失败历史**不足，运营难排障。

### 4.4 推进顺序（锁定依赖）

```
第一阶段 平台基础
  管理员权限 → 来源可见性/审核态 → 私有数据隔离
  → RSS 出站安全 → Feed 健康与失败重试

第二阶段 核心用户闭环
  公共目录 + 中科院分类
  → 自定义 RSS 预览 / 私有添加 / 公开申请
  → 单来源实时·每日 + Email 主通道 + 微信增强
  → 已读 / 收藏 / 稍后阅读 + 原文跳转

第三阶段 目录冷启动
  200～300 验证来源
  → 正式期刊 vs 预印本
  → arXiv 等预印本
  → Crossref 补 DOI（按需）
  → PubMed 是否接入：用数据决定，不默认必做

第四阶段 内测验证
  种子用户 → 激活/活跃/原文点击/收藏/退订
  → 抓取失败、重复、推送失败统计
  → 再决定 AI 摘要、学校分区或扩大数据源（均非本 spec 范围）
```

**禁止**在未完成第一阶段隔离与 SSRF 的情况下，仅靠堆 seed 或先做阅读状态宣称「可内测」。

现有 `data/journals_seed.json` + `scripts.seed_journals` 是冷启动**工具链雏形**，体量与校验深度需在第三阶段升级到验收标准。

### 4.5 测试重点

- RSS 2.0 / Atom / RDF 与异常编码样例；  
- DOI / GUID / URL 多级去重；  
- 私有来源权限隔离（API 与列表双测）；  
- Feed URL 安全校验（含重定向）；  
- 审核流与重复来源合并；  
- 实时 vs 每日推送分流；  
- Email / 微信失败重试与通道隔离；  
- 从导入到跳转原文的端到端流程。

## 5. 与现网（FastAPI 迁移后）的关系

| 保留 | 变更 |
|------|------|
| Python 3.12 + FastAPI 单体、SPA 托管、小程序同 API | 产品语义从「迁移对等」升级为「线索平台 v1」 |
| PostgreSQL + Redis、APScheduler | Journal/订阅/通知模型扩展；阅读状态新表；分类新表 |
| 抓取 → 去重 → 匹配 → 通知 思路 | 去重升为 DB 最终防线；推送任务化与重试；健康字段 |
| Email + 微信通道 | 明确主/增强；订阅级频率与通道开关 |
| 用户 RSS preview/create、journal requests | 私有/公开审核态；SSRF  hardening |
| 内置 seed 期刊 | 扩展为经校验的 200–300 公共目录冷启动 |
| 迁移设计中「Admin 无 RBAC」 | **本 spec 明确废止**：内测前必须有管理员角色 |

迁移设计文档仍是**技术栈基线**；**产品与权限以本文为准**。冲突时以本文（v1 产品）优先。
